OctopusFile

Um conjunto de ferramentas para ficheiros em Java 17+ sem bibliotecas externas: tudo assenta no JDK (java.nio.file, java.net.http, javax.crypto, java.util.zip).

É o motor do gestor de ficheiros FileExp e cobre aquilo que uma aplicação de secretária ou de servidor que trabalha muito com ficheiros costuma ter de escrever à mão: transferências com progresso e cancelamento, um Lixo com restauro, um índice de nomes instantâneo, mudar o nome em lote com pré-visualização, pesquisa de duplicados, análise do disco, cópias de segurança e sincronização, um cofre cifrado, armazenamento WebDAV e SMB, e partilha de ficheiros cifrada na rede local.

javaOctopusFile octo = OctopusFile.of();

octo.write(Path.of("notes.txt")).text("hello\n");
octo.copy("notes.txt").to("backup/notes.txt");
TrashEntry gone = octo.moveToTrash("backup/notes.txt");   // restorable
octo.restoreFromTrash(gone.getId());

Os pacotes e tipos internos estão marcados com @Internal. Só são públicos em termos de Java porque outros pacotes do OctopusFile os usam; podem mudar em qualquer versão. O mesmo se aplica aos construtores dos módulos que recebem tipos internos (por exemplo FileMover(NIO2FileSystem, FileValidator, …)): use o construtor sem argumentos.

Desde a 1.2.0 o JAR é o módulo com.octopusfile: os pacotes internos não são exportados — consulte module-info.java. No classpath o JAR funciona como antes.

Regras de conceção#

  • Sem dependências externas. Um runtime criado com jlink precisa de java.base, java.net.http (WebDAV, transferências), java.xml (WebDAV) e jdk.crypto.ec (Partilha local).
  • Chamadas bloqueantes, threads explícitas. Os métodos bloqueiam; o trabalho demorado passa pelo TransferManager (progresso, cancelamento) ou pelo seu próprio executor. Nenhum método precisa de uma thread de interface.
  • Nunca substituir de surpresa. Cópias, movimentos, extrações e ficheiros recebidos recebem nomes livres (photo (2).jpg).
  • Os erros são valores com que se pode agir. Um único tipo de exceção, OctopusFileException, com um valor de ErrorCodes.
  • Cancelar em tudo o que pode demorar. As operações demoradas recebem um AtomicBoolean, um BooleanSupplier ou correm como uma Transfer que pode cancelar.

Requisitos#

Java 17 ou mais recente. Testado no Windows 11; os caminhos de código para Linux e macOS (montagens, gio, /Volumes) existem, mas precisam de mais testes.
