Road to 2.0 (LTS)

OctopusFile 2.0 will be the official long-term support (LTS) version. Version 1.4 is the last 1.x feature release: it adds what 2.0 builds on and marks, with @Deprecated(forRemoval = true), what 2.0 removes. Code that compiles on 1.4 without removal warnings is ready for 2.0.

What LTS will mean#

Fixes2.0.x versions with bug and security fixes only — no new features, no API changes
APIno breaking change in the whole 2.x line; anything deprecated in 2.x is removed only in 3.0
Formatseverything written by 2.0 (vault, encrypted files, snapshot repositories, saved index) stays readable by every later version
JavaJava 17 and newer; tested on Windows, Linux and macOS by the CI
Dependenciesstill none

The length of the support period will be announced with 2.0.

Removed in 2.0#

Deprecated in 1.4Use instead
FileManager, OctopusFile.getFileManager()the OctopusFile facade (copy, move, delete, write) or java.nio.file.Files
DirectoryManager, getDirectoryManager()OctopusFile.list(...), createDirectory(...) or Files
BatchOperations, getBatchOperations()a loop, or TransferManager for long work with progress and cancel
AsyncOperations, getAsyncOperations()CompletableFuture or TransferManager

To find the uses in your code, compile with -Xlint:removal (javac lists every use as a warning).

Planned for 2.0#

  • One way to do each thing: Path in every public method (the String versions become shortcuts of the facade only).
  • Long operations return a Transfer (progress, cancel) everywhere, including snapshot backups and content search.
  • Snapshot repositories on WebDAV storage, so a backup can go to a cloud.
  • The modules keep their package names and the module stays com.octopusfile.
