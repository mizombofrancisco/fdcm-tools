Backup and sync

javaOctopusFile octo = OctopusFile.of();

BackupMetadata zip = octo.backup(docs).to(usb.resolve("zips"));      // Documents-<date>.zip
SyncResult copy = octo.sync(docs, usb.resolve("Documents"), false);  // only new and changed
SyncResult mirror = octo.sync(docs, usb.resolve("Documents"), true); // also removes what was deleted

Backups — BackupService#

A ZIP of a file or folder named with the original name and a timestamp, so a backup never replaces another. backup(path).restoreTo(dir) extracts it. BackupScheduler runs backups at a fixed rate.

Snapshots — SnapshotRepository (since 1.4)#

Incremental, deduplicated and optionally encrypted backups. Each backup records the whole folder as a snapshot, but only content the repository does not have yet is stored:

javatry (SnapshotRepository repo = SnapshotRepository.create(usb.resolve("Backups"), "a long password".toCharArray())) {
    SnapshotRepository.Snapshot s = repo.backup(docs, "Documents", null, null);
    System.out.println(s.files() + " files, " + s.bytesAdded() + " new bytes");

    repo.restore(s, restoreFolder, null, null, null);       // never overwrites: the folder must be empty
    repo.restore(s, photosOnly, p -> p.startsWith("Photos/"), null, null);
    repo.prune(10);                                         // keep the last 10 snapshots of each label
    List<String> problems = repo.verify(null);              // read everything back
}
// later: SnapshotRepository.open(usb.resolve("Backups"), password)
Incrementala file with the same size and date as in the previous snapshot of the same label is not read again
Deduplicatedidentical content is stored once, across files, folders and snapshots
CompressedDeflate, except formats that are already compressed (JPEG, MP4, ZIP, DOCX…)
Encrypted (with a password)AES-256-GCM in authenticated 1 MiB blocks, key from PBKDF2-HMAC-SHA256 (310 000 iterations); stored objects are named by an HMAC, so names reveal nothing; file names, sizes and dates are in encrypted snapshot files
Safeeverything is written to a temporary file and renamed; a lock file keeps two programs out; restore refuses a non-empty folder; every restored byte is checked against its hash
Maintenanceprune(keepPerLabel), delete(snapshot), verify(cancel), sizeOnDisk()

A file that cannot be read (in use, no permission) is listed in Snapshot.failed() and the rest continues. Setting the cancel flag stops a backup without recording anything. There is no recovery without the password.

In the cloud — push and pull (since 2.0)#

A repository can be copied to a WebDAV folder (Nextcloud, ownCloud, a NAS…) and brought back:

javaWebDavStorage cloud = new WebDavStorage("https://cloud.example.com/remote.php/dav/files/ana/", "ana", appPassword);
SnapshotRepository.SyncReport sent = repo.push(cloud, "/Backups/Laptop", null, null);    // only what is missing

// on another computer, or after losing the disk:
SnapshotRepository.pull(cloud, "/Backups/Laptop", newFolder, null, null);
try (SnapshotRepository copy = SnapshotRepository.open(newFolder, password)) {
    copy.restore(copy.list().get(copy.list().size() - 1), restoreFolder, null, null, null);
}

Stored content never changes once written, so push sends only the files the cloud does not have (content first, snapshots last, each file under a temporary name and then renamed) and removes in the cloud what prune or delete removed here; pull fetches only what is missing and deletes nothing locally. An encrypted repository stays encrypted in the cloud. For progress and cancel, use TransferManager.pushSnapshots / pullSnapshots (transfers). Only one computer should push to a cloud folder.

Sync — DirectorySynchronizer#

One-way synchronisation from a source folder to a target:

ModeEffect
mirror = falsecopies files that are new or changed (size or a newer date, compared to the millisecond; on FAT32 drives a difference under 2 s is ignored); never deletes
mirror = truethe same, and deletes from the target what no longer exists at the source

SyncResult lists what was copied, updated, deleted and what failed (files in use or without permission are skipped; the rest continues). For progress, call plan(source, target) to know the bytes and files to copy, then sync(source, target, mirror, (file, bytes) -> …); throwing from the callback cancels.

Safety: a mirror deletes in the target. Point it at a folder dedicated to the backup (FileExp always uses <target>/FileExp Backup/<folder name>), never at the root of a drive. The target can never be inside the source.
