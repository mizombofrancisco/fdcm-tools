Disk analysis and treemap

DiskAnalyzer walks a folder once and returns everything a "what fills my disk" screen needs. Only folders are kept in memory (not one object per file), so it handles hundreds of thousands of files.

javaDiskAnalyzer.Result r = new DiskAnalyzer().top(20).analyze(folder, n -> { }, new AtomicBoolean());
System.out.println(r.root.size() + " bytes in " + r.root.fileCount() + " files");
for (DiskAnalyzer.Folder f : r.root.children()) {          // largest first
    System.out.println(f.name + "  " + f.size());
}
for (DiskAnalyzer.Category c : r.categories) {             // images, videos, music, documents, ...
    System.out.println(c.id() + "  " + c.bytes());
}
Result fieldContent
rootfolder tree with total size, own files size and file count
largestthe N largest files
oldLargelarge files not changed for a long time (old(ageMillis, minSize), default 6 months / 50 MB)
emptyFoldersfolders without files
categoriesbytes and files per kind (DiskAnalyzer.category(name) maps an extension)
cancelled, elapsedMillisthe walk was stopped / how long it took

Hidden items and folders like node_modules, AppData, .git are skipped by default (skipHidden, skipNames). The progress callback receives the number of files seen.

Treemap layout#

TreemapLayout.squarify turns sizes (largest first) into rectangles with areas proportional to the sizes and shapes close to squares — ready to draw in any UI toolkit.

javadouble[] sizes = r.root.children().stream().mapToDouble(DiskAnalyzer.Folder::size).toArray();
List<TreemapLayout.Rect> rects = TreemapLayout.squarify(sizes, 0, 0, 800, 400);
// each Rect: x, y, w, h and index (the position in sizes)
