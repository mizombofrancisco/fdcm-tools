Batch rename

BatchRenamer renames many files at once. It works in two steps: a plan (new names and problems, without touching the disk — fast enough to recompute on every key press) and apply (all or nothing).

javaBatchRenamer.Rule rule = new BatchRenamer.Rule();
rule.template = "Holiday {n}";  // also {name}, {date}, {ext}
rule.digits = 2;
BatchRenamer.Plan plan = BatchRenamer.plan(photos, rule, null);
for (BatchRenamer.Entry e : plan.entries) {
    System.out.println(e.source.getFileName() + " -> " + e.newName + (e.problem == null ? "" : "  (" + e.problem + ")"));
}
if (!plan.hasProblems()) {
    BatchRenamer.renameAll(plan.pairs());   // all or nothing
}

Rule#

Applied in this order, by default to the name without its extension:

FieldEffect
templatereplaces the name: {name} original name, {n} counter (start, zero-padded to digits), {date} modified date yyyy-MM-dd, {ext}
find, replace, regex, matchCasefind and replace, plain text or regular expression ($1 groups)
prefix, suffixadd text
letterCaseKEEP, LOWER, UPPER, TITLE
includeExtensionapply the rules to the extension too

Problems found by the plan#

Duplicate name (two files would get the same name), Already exists (a file not being renamed has that name), Invalid characters, Empty name, Name too long, Invalid regular expression, plus your own check: the third argument of plan is a Function<String, String> returning an error or null (for example the rules of your operating system).

Apply#

renameAll(pairs) uses temporary names only where needed (swaps like a → b and b → a, letter-case changes on Windows/macOS) and undoes every rename if one fails. It returns the pairs applied, which can be passed back reversed to undo.

For big selections, read the attributes once with BatchRenamer.prepare(files) and call plan(prepared, rule, check) on every change: 5 000 names in about 0.1 s.
