Compilar, executar e testar

O que é preciso#

FerramentaVersãoOnde
JDK17C:\Program Files\Java\jdk-17.0.18
JavaFX SDK17C:\Program Files\Java\javafx-sdk-17-0-18 (para compilar e executar)
JavaFX jmods17C:\Program Files\Java\javafx-jmods-17.0.18 (para empacotar)
NetBeans18 (com o seu Ant)para abrir o projeto
WiX Toolset3.11apenas para o instalador do Windows
Python3apenas para as traduções e o site da documentação

Abrir o projeto#

Abra a pasta FileExp no NetBeans (File › Open Project). É um projeto Ant normal (nbproject/); os módulos JavaFX estão em run.jvmargs em nbproject/project.properties.

Compilar fora do IDE#

O Ant do próprio NetBeans pode ser usado a partir de um terminal. Em PowerShell:

powershell& "C:\Program Files\NetBeans-18\netbeans\extide\ant\bin\ant.bat" -q "-Duser.properties.file=$env:APPDATA\NetBeans\18\build.properties" jar

O resultado é dist/FileExp.jar. Os outros alvos usam-se da mesma forma (substitua jar):

AlvoResultado
jarCompila e cria dist/FileExp.jar
runCompila e executa
selftestOs testes automáticos
package-exedist/package/image/FileExp/FileExp.exe — aplicação portátil com o seu próprio Java
package-installerdist/package/installer/FileExp-x.y.z.exe — instalador do Windows (precisa do WiX)
package-debPacote Debian/Ubuntu (executar em Linux, -Djavafx.jmods=/path/to/javafx-jmods-17)

build-installer.bat faz o pacote completo do Windows num só passo.

Se o FileExp estiver aberto a partir de dist/package, os seus ficheiros ficam bloqueados. Em vez de o fechar, empacote para outra pasta: -Dpkg.dir=dist/package-3.7.2.

Testes automáticos#

Os testes estão em selftest/ e usam um pequeno executor de testes feito para o projeto (sem JUnit):

powershellant selftest                        # cerca de meio minuto
ant selftest -Dselftest.mode=all    # também o teste de desempenho com 50 000 ficheiros
ant selftest -Dselftest.mode=perf   # apenas o teste de desempenho

Correm com uma pasta pessoal temporária (build/selftest/home), pelo que os seus dados reais nunca são tocados.

Classe de testeAbrange
FileOperationsTestCopiar, mover, mudar o nome, Lixo, nomes que têm de ser recusados
BatchRenamerTestModelos, conflitos, trocas, tudo-ou-nada
UndoHistoryTestAnular/refazer de todas as operações
ZipTestComprimir, extrair, zip slip
TransferTestProgresso, conflitos de nomes, cancelar, origem em falta
StoreTestO armazenamento NoSQL: os documentos sobrevivem à reabertura, procurar, remover
WebDavTestUm servidor WebDAV local real
Phase2TestFiltros de pesquisa, índice, pesquisa no conteúdo, análise do disco, duplicados, cópias de segurança, endereços SMB
Phase3TestCofre, etiquetas, regras, registo e sessões da linha do tempo
Phase4TestAtalhos, Partilha local entre dois "computadores" num só PC
PerformanceTest50 000 ficheiros: listagem, ordenação e pesquisa; mudança de nome em lote de 5 000 ficheiros

Escrever um teste: adicione uma classe com métodos marcados com @Test, use as asserções de TestRunner (check, equal) e registe a classe em TestRunner.

Integração contínua#

Cada push e pull request para o GitHub executa .github/workflows/ci.yml em Windows e Linux:

  1. compila o FileExp e executa ant selftest;
  2. python i18n/build_tsv.py --check — falha se um texto do código não tiver tradução, ou se o strings.tsv não tiver sido gerado de novo;
  3. python docs/fileexp/build_site.py — falha se uma página ou uma captura existir num idioma e não no outro.

Todas as segundas-feiras corre também o teste de desempenho (50 000 ficheiros); pode ainda ser iniciado à mão em GitHub › Actions › CI › Run workflow.

O trabalho é feito por ci/ci.py, por isso pode executar exatamente o mesmo no seu computador antes do push:

powershellpython ci/ci.py                  # compilar + testes rápidos + traduções + documentação
python ci/ci.py --mode all       # também o teste de desempenho
python ci/ci.py --only checks    # só traduções e documentação (alguns segundos)

Não precisa do NetBeans: o JavaFX 17.0.18 é descarregado uma vez do Maven Central (verificado com o SHA-1) para build/ci/javafx, e o Ant recebe um ficheiro de propriedades vazio, só com o classpath do JavaFX. Uma CI vermelha bloqueia a publicação (consulte Publicar uma versão).

Escala de apresentação (125 %, 150 %, 200 %)#

Num ecrã de 1920x1080, o Windows a 200 % deixa só 960x510 píxeis lógicos: é aí que os layouts se partem. Verifique cada alteração que mexa no ecrã com:

powershellpython tools/scale/scale_check.py                   # 100, 125, 150 e 200 % (cerca de 4 minutos cada)
python tools/scale/scale_check.py --scales 2.0      # só a mais difícil

Abre o FileExp com uma pasta pessoal de demonstração (build/scale/home, por isso os seus ficheiros nunca são usados nem mostrados), percorre os ecrãs principais e todas as páginas das Definições, e guarda cada um em píxeis físicos em build/scale/<escala>/ com um audit.txt. A auditoria lista texto cortado com "…" e tudo o que sai da janela; termina com código 1 se houver algum. Texto cortado de propósito (caminhos longos, cortados no meio) não conta.

Regras aprendidas a 200 %:

  • Um contentor que pode ser mais alto do que o ecrã (a coluna de widgets, a lista de páginas das Definições, um diálogo longo) vai numa área com deslocamento com minHeight="0": senão a sua altura mínima empurra a barra superior para fora da janela.
  • Uma camada escondida tem de sair do layout: managed ligado a visible, senão o seu tamanho mínimo continua a contar.
  • Os ícones de cor são descodificados a 2x (IconFINDER.named): um ImageView com eles precisa sempre de fitWidth/fitHeight.

Verificar a interface sem tocar no seu ambiente de trabalho#

Para alterações no ecrã, uma pequena classe harness pode arrancar o FileExp com uma pasta pessoal falsa e guardar imagens da cena:

powershelljava "-Duser.home=C:\scratch\fakehome" --module-path "C:\Program Files\Java\javafx-sdk-17-0-18\lib" `
     --add-modules javafx.controls,javafx.fxml,javafx.swing,javafx.media -cp "build\classes;harness" MyHarness

O harness chama Platform.runLater, conduz os controllers e guarda scene.snapshot(null) como PNG. Nunca ative a Partilha local nem faça bind a 0.0.0.0 num harness: isso faz com que a firewall do Windows pergunte ao utilizador.

O site da documentação#

bashpython docs/fileexp/build_site.py       # este site (inglês e português)

Lê as páginas Markdown e escrevem HTML, CSS e JavaScript simples em site/. Abra site/index.html diretamente num navegador.
