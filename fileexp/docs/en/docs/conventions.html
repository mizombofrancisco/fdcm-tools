Conventions and rules

These rules keep FileExp coherent from version to version. A change that breaks one of them needs a very good reason, written in the changelog.

The non-negotiable rules#

  1. No external libraries. Only the JDK, JavaFX and the project's own packages. Need something (JSON, HTTP, crypto, ZIP)? It is either in the JDK or written in the file engine.
  2. NetBeans/Ant project. No Maven or Gradle in the application. Targets are added to build.xml.
  3. The user's data goes to the NoSQL store (ao.fileexp.store) — never to .properties files, the registry or a separate database.
  4. FXML is extended, not rewritten. Add nodes following the existing pattern: the style classes of desktop.css (the theme comes from theme-dark/theme-light on the root), <Icon name=".." size=".."/> for symbolic icons, colours from CSS variables.
  5. Every text on screen is translated. In code, I18n.tr("English text"); in FXML, the English text is translated by I18n.translate(root). Each new text gets a line in i18n/translations-*.txt.
  6. Nothing is lost by surprise. Never overwrite (choose a free name), delete through the Trash, make operations undoable, ask before anything that cannot be undone.
  7. No system windows. Menus and dialogs are drawn in the scene (Overlays, Popover, Dialogs).
  8. Use the file engine for file work. Do not call java.nio.file.Files from the screens; if the engine lacks something, add it there, in English, with a test.

Code style#

  • Java 17, 4 spaces, braces always, one top-level class per file.
  • Names, comments and logs in English.
  • Package-private by default; @Internal on file engine code that is not public API.
  • A class that only holds logic goes to control; a class that holds user data goes to data.

Performance rules (learned on folders with 50 000 files)#

  • List folders with Files.walkFileTree at depth 1 (or the engine's listing): attributes come with the listing, not one disk call per file.
  • Never create a Tooltip per tile — each one is a window with its own scene. Create it when the mouse enters.
  • Draw many tiles in blocks, one block per frame.
  • Cache what the system answers slowly (free space, drive labels).
  • Anything that can take more than ~50 ms runs in the background and comes back with Platform.runLater.

Threads and JavaFX#

  • Touch nodes only on the JavaFX thread.
  • Never block the JavaFX thread on a file operation; use the transfers queue for anything long, so the user sees progress and can cancel.
  • Dialogs uses a nested event loop: do not call it from a background thread.

Security rules#

  • Passwords of accounts are stored encrypted (CredentialVault); SMB passwords are never stored.
  • Received or extracted names are cleaned: no .., no absolute paths, no drive letters.
  • Network features are off by default and bind only to the needed address.

Tests#

  • Each feature comes with tests in selftest/, run with ant selftest before every build that goes to users.
  • Tests use the temporary home folder; they never touch the real one.

Changelog#

Every change that a user can notice goes to CHANGELOG.md (in Portuguese), under "Por publicar" until the version is released.
