Building, running and testing

What you need#

ToolVersionWhere
JDK17C:\Program Files\Java\jdk-17.0.18
JavaFX SDK17C:\Program Files\Java\javafx-sdk-17-0-18 (to compile and run)
JavaFX jmods17C:\Program Files\Java\javafx-jmods-17.0.18 (to package)
NetBeans18 (with its Ant)to open the project
WiX Toolset3.11only for the Windows installer
Python3only for translations and the documentation website

Opening the project#

Open the folder FileExp in NetBeans (File › Open Project). It is a standard Ant project (nbproject/); the JavaFX modules are in run.jvmargs in nbproject/project.properties.

Building outside the IDE#

NetBeans' own Ant can be used from a terminal. In PowerShell:

powershell& "C:\Program Files\NetBeans-18\netbeans\extide\ant\bin\ant.bat" -q "-Duser.properties.file=$env:APPDATA\NetBeans\18\build.properties" jar

The result is dist/FileExp.jar. Other targets are used the same way (replace jar):

TargetResult
jarCompile and build dist/FileExp.jar
runBuild and run
selftestThe automatic tests
package-exedist/package/image/FileExp/FileExp.exe — portable app with its own Java
package-installerdist/package/installer/FileExp-x.y.z.exe — Windows installer (needs WiX)
package-debDebian/Ubuntu package (run on Linux, -Djavafx.jmods=/path/to/javafx-jmods-17)

build-installer.bat does the whole Windows package in one step.

If FileExp is open from dist/package, its files are locked. Package to another folder instead of closing it: -Dpkg.dir=dist/package-3.7.2.

Automatic tests#

The tests are in selftest/ and use a small test runner made for the project (no JUnit):

powershellant selftest                        # about half a minute
ant selftest -Dselftest.mode=all    # also the 50 000-file performance test
ant selftest -Dselftest.mode=perf   # only the performance test

They run with a temporary home folder (build/selftest/home), so your real data is never touched.

Test classCovers
FileOperationsTestCopy, move, rename, Trash, names that must be refused
BatchRenamerTestTemplates, conflicts, swaps, all-or-nothing
UndoHistoryTestUndo/redo of every operation
ZipTestCompress, extract, zip slip
TransferTestProgress, name clashes, cancel, missing source
StoreTestThe NoSQL store: documents survive reopening, find, remove
WebDavTestA real local WebDAV server
Phase2TestSearch filters, index, content search, disk analysis, duplicates, backups, SMB addresses
Phase3TestVault, tags, rules, journal and timeline sessions
Phase4TestShortcuts, Share nearby between two "computers" on one PC
PerformanceTest50 000 files: listing, sorting and search; batch rename of 5 000 files

Writing a test: add a class with methods marked @Test, use the assertions of TestRunner (check, equal), and register the class in TestRunner.

Continuous integration#

Every push and pull request to GitHub runs .github/workflows/ci.yml on Windows and Linux:

  1. compile FileExp and run ant selftest;
  2. python i18n/build_tsv.py --check — fails if a text of the code has no translation, or if strings.tsv was not rebuilt;
  3. python docs/fileexp/build_site.py — fails if a page or a screenshot exists in one language and not in the other.

Every Monday the performance test (50 000 files) runs too; it can also be started by hand in GitHub › Actions › CI › Run workflow.

The work is done by ci/ci.py, so you can run exactly the same thing on your computer before you push:

powershellpython ci/ci.py                  # build + quick tests + translations + documentation
python ci/ci.py --mode all       # also the performance test
python ci/ci.py --only checks    # only translations and documentation (a few seconds)

It does not need NetBeans: JavaFX 17.0.18 is downloaded once from Maven Central (checked with its SHA-1) into build/ci/javafx, and Ant gets an empty user properties file with only the JavaFX classpath. A red CI blocks the release (see Publishing a release).

Display scaling (125 %, 150 %, 200 %)#

On a 1920x1080 screen, Windows at 200 % leaves only 960x510 logical pixels: that is where layouts break. Check every change that touches the screen with:

powershellpython tools/scale/scale_check.py                   # 100, 125, 150 and 200 % (about 4 minutes each)
python tools/scale/scale_check.py --scales 2.0      # only the hardest one

It opens FileExp with a demo home folder (build/scale/home, so your own files are never used or shown), goes through the main screens and every Settings page, and saves each one in physical pixels in build/scale/<scale>/ with an audit.txt. The audit lists text cut with "…" and anything that goes out of the window; the exit code is 1 if there is any. Text cut on purpose (long paths, cut in the middle) is not counted.

Rules learned at 200 %:

  • A container that can be taller than the screen (the widgets column, the list of Settings pages, a long dialog) goes in a scroll pane with minHeight="0": otherwise its minimum height pushes the top bar out of the window.
  • A hidden layer must leave the layout: managed bound to visible, or its minimum size still counts.
  • Colour icons are decoded at 2x (IconFINDER.named): an ImageView of them always needs fitWidth/fitHeight.

Checking the interface without touching your desktop#

For changes on screen, a small harness class can start FileExp with a fake home folder and save images of the scene:

powershelljava "-Duser.home=C:\scratch\fakehome" --module-path "C:\Program Files\Java\javafx-sdk-17-0-18\lib" `
     --add-modules javafx.controls,javafx.fxml,javafx.swing,javafx.media -cp "build\classes;harness" MyHarness

The harness calls Platform.runLater, drives the controllers and saves scene.snapshot(null) as PNG. Never enable Share nearby or bind to 0.0.0.0 in a harness: it makes the Windows firewall ask the user.

The documentation website#

bashpython docs/fileexp/build_site.py       # this site (English and Portuguese)

It reads the Markdown pages and write plain HTML, CSS and JavaScript to site/. Open site/index.html directly in a browser.
