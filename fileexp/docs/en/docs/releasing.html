Publishing a release

A step-by-step checklist to go from the code to an installer users can trust.

1. Prepare#

  1. Choose the number (see Version numbers).
  2. Change it in src/ao/fileexp/FileExp.java (VERSION) and in build.xml (pkg.version). Then build from clean: delete build/classes (not ant clean, which also deletes dist/). VERSION is a constant that Java copies into the classes that use it (Settings › About, the error report): an incremental build keeps the old number there.
  3. In CHANGELOG.md, rename "Por publicar" to the version and date, for example ## 3.8.0 (02/12/2026) — Title.
  4. Run python i18n/build_tsv.py — it must report no missing translations.

2. Test#

powershellant jar
ant selftest
ant selftest -Dselftest.mode=all

Or simply python ci/ci.py --mode all. All tests must pass, and the CI must be green on Windows and Linux for the commit you release (GitHub › Actions). Then check by hand, at least in English and Portuguese:

  • first run with an empty home (setup assistant, licences, welcome);
  • browse, copy, rename many, delete, undo, redo;
  • search with filters and inside files;
  • quick look of an image, a text and a ZIP;
  • Settings: every page opens;
  • the new features of this version.
  • python tools/scale/scale_check.py reports no problem at any scale, also with --lang pt (longer texts) (see Building and testing).

3. Package#

powershellant "-Dpkg.dir=dist/package-3.8.0" package-installer

Results:

  • dist/package-3.8.0/image/FileExp/ — portable app;
  • dist/package-3.8.0/installer/FileExp-3.8.0.exe — installer.

On Linux, ant package-deb -Djavafx.jmods=/path/to/javafx-jmods-17.

4. Check the package#

  • Install on a clean user account (or a virtual machine).
  • The icon, name, version and publisher (Muendu Studio) are right in the installer and in Settings › About.
  • Start, open a folder, quick look a video (the javafx.media module is included), quit.
  • Uninstall: the app goes, ~/.fileexp stays.

5. Documentation#

  • Update the pages of the new features, in English and Portuguese.
  • Update the screenshots if screens changed.
  • Add the version to the version history (both languages).
  • python docs/fileexp/build_site.py and open the site.

6. Publish#

  • Commit, tag v3.8.0, push the commit and the tag. The Release workflow creates the GitHub Release with the JAR and the section of the version in CHANGELOG.md.
  • Attach the installer to that Release: GitHub › Releases › the version › Edit › drag FileExp-<version>.exe from dist/package-<version>/installer/ › Update release — or gh release upload v<version> dist/package-<version>/installer/FileExp-<version>.exe. Since 3.11.3 installers are not kept in git (dist/package-*/ is in .gitignore): an installer is over 50 MB, and GitHub warns about every file that size on push. Files attached to a Release can be up to 2 GB.
  • Publish the portable app folder (zipped by hand) and the .deb the same way, if made.
  • Keep the installer of the previous version available.
