Architecture

FileExp is a JavaFX 17 desktop application written in Java 17, built with NetBeans/Ant. It uses no external libraries: only the JDK, JavaFX and its own internal packages.

Packages#

PackageResponsibility
ao.fileexpFileExp — the Application class, the version (FileExp.VERSION) and the start-up sequence.
ao.fileexp.desktopEverything on screen: DesktopController (desktop, top bar, widgets, notifications), LauncherController (My Files, with its parts — see below), SettingsController, SplashController, and the views DiskHealthView, TimelineView, VaultView, QuickLook, SplitPanel, TransfersPanel, Treemap, plus Overlays/Popover (menus drawn inside the scene), Icon (vector icons usable in FXML), Theme and Ui helpers.
ao.fileexp.windowDialogs — confirmations, questions and forms drawn inside the scene, with a nested event loop.
ao.fileexp.controlLogic without screens: FileOperations, Places, UndoHistory, SearchFilter, HomeIndex, Timeline, RulesEngine, Shortcuts, VaultSession, Nearby, FolderWatcher, DefaultDirs, IconFINDER.
ao.fileexp.dataThe user's data on top of the store: DataContext (entry point), AppSettings, UserProfile, ActivityTracker, Journal, Tags, SmartCollections, Rules, BackupJobs, CloudAccounts, NetworkPlaces.
ao.fileexp.storeThe embedded NoSQL document store: DocumentStore, DocumentCollection, Document, Json.
ao.fileexp.i18nI18n — translations from strings.tsv.
ao.fileexp.octopusfileThe file engine, built with OctopusFile: operations, Trash, transfers, search index, duplicates, analysis, ZIP, backup/sync, WebDAV, vault, LAN sharing.
ao.fileexp.style, theme, wallpapersdesktop.css, PNG icons, wallpapers.

My Files inside#

LauncherController is the FXML controller of My Files: it owns the nodes, the state (location, items, selection set, history) and the flow — navigation, loading, rendering the tiles, the toolbar and the keys. The rest lives in parts of the same package, each created once by the controller and reaching it through a field lc:

PartDoes
SelectionModelSelect one, a range (Shift), all, none; keeps the tiles and the details in step
FileActionsCopy, cut, paste, delete, rename, new folder and text file, ZIP, Send to, Undo/Redo, Trash, and the background runner of these operations
ContextMenusRight click on an item or on the background, the View, New, Tags and Send to menus
DetailsPanelThe panel on the right: file, folder size, drive, cloud account, location
TabsControllerTabs, each with its own history, selection and scroll
SplitViewTwo panels side by side, drag and drop
DeepSearchThe home index, walking subfolders, content:
PlaceItemsTags, smart collections, network, cloud, synced folders, system folders, drives
CloudActionsWebDAV accounts: connect, open, download, upload, delete
BatchRenameDialogRenaming many files at once, with a live preview

A new feature of My Files goes to the part it belongs to, or to a new part made the same way — not back into LauncherController.

Layers#

text FXML + controllers (desktop, window)      <- what the user sees
            |
 control  (operations, search, rules...)   <- logic, testable without a screen
            |
 data     (settings, tags, journal...)     <- the user's data, as JavaFX properties
            |
 store    (JSON document collections)      <- persistence, atomic writes
            |
 octopusfile (file engine, JDK only)       <- every touch of the file system

Rules: the screens call control and data; control uses octopusfile for all file work; nothing below desktop imports JavaFX controls. The file engine does not know FileExp exists.

Start-up#

  1. FileExp.main checks whether this user already has a FileExp open (control/SingleInstance, since 3.11): if so, it hands over the folders and files of the command line and ends.
  2. FileExp.start shows the splash (Splash.fxml) — at least 3.4 s for the animation.
  3. In the background: DataContext.open() opens the store in ~/.fileexp/data, the language is chosen, the file engine is prepared.
  4. Desktop.fxml is loaded and DesktopController.welcome() decides what appears (since 3.11):
    • on the first run, the setup assistant (desktop/SetupWizard, 10 steps);
    • for someone who already used FileExp but has not accepted the current version of the licences, only the licence page;
    • otherwise, the "Welcome back" notification.

After that, the folders and files of the command line open with desktop/OpenFiles.

  1. Background services start: the home index, the folder watcher, the rules engine (every 30 s), automatic backups (on drive plug-in), and Share nearby if enabled.

The data store#

ao.fileexp.store keeps collections of JSON documents, one file per collection in ~/.fileexp/data:

CollectionContent
settingsAll preferences (AppSettings turns each into a JavaFX property that saves itself)
usersProfile and sessions
activityCount and last access of opened files and folders
favoritesFavourites
journalTimeline events (last 5 000)
tags, tagdefsTags on files, and tag names/colours
collectionsSmart collections
rulesAutomations
backupsBackup jobs
cloudWebDAV accounts (passwords encrypted)
networkSaved SMB servers

Writes are done in the background, atomically (temporary file + rename) and keep a .bak of the previous version.

Threads#

  • The JavaFX thread only builds and updates the interface.
  • File work runs on background executors (the engine's TransferManager, the index, analyses) and returns with Platform.runLater.
  • Dialogs use a nested event loop (Dialogs), so code can ask a question and wait for the answer without blocking the screen.

Interface#

  • One Stage; everything else (menus, dialogs, previews, windows such as Settings) is drawn in the scene by Overlays, Popover and Dialogs, so it follows the theme and never opens system windows.
  • The FXML files (Desktop, Launcher, Settings, Splash, InternalWindow) use the style classes of desktop.css and <Icon name="…" size="…"/> for symbolic icons; Theme puts theme-dark or theme-light on the root, and colours come from desktop.css variables (-fe-bg, -fe-accent…).
  • Tiles of a folder are drawn in blocks, one block per frame, and tooltips are created only when the mouse is over a tile.
